# PhoneMic 通信协议 v1

手机 ↔ PC Agent 之间走 **WebSocket**，一帧一条消息，默认 **JSON 文本帧**。
两端的实现在 `pc-agent/agent/protocol.py` 与 `android/.../net/Protocol.kt`，**本文档是唯一权威**，改动需同步三处。

---

## 1. 连接

- URL：`ws://<pc-lan-ip>:<port>`（默认 `8765`）
- 由手机主动连接 PC；PC 不反向连接
- WebSocket ping/pong 保活（20 s），断线后手机端指数退避重连（1 s → 30 s 封顶）

## 2. 配对

PC 端生成二维码，内容形如：

```
phonemic://192.168.1.3:8765?v=1&t=<token>&n=<电脑名>
```

| 字段 | 说明 |
|---|---|
| `v` | 协议版本，当前 `1` |
| `t` | 配对令牌，24 字节 url-safe base64，**跨重启保持不变** |
| `n` | 电脑显示名（`urllib.parse.quote` 百分号编码），显示在手机悬浮球上。**可选**：旧版手机忽略它，回退用 `auth_ok.device_name` |

令牌也可在设置页手动输入（`192.168.1.3:8765?t=xxx&n=客厅电脑`）。
手机连上后**第一条消息必须是 `auth`**，否则后续一律回 `error: unauth`。

### 多电脑

一次配对只绑定**一台**电脑；同一个手机可以绑定多台（各自独立的令牌与 `n`），
手机侧保存为一张列表，`auth_ok.device_name` 始终用来回填/校正该条记录的名字。
当前目标由手机侧决定，**切换 = 手机断开旧连接、对新目标重新走一遍 `auth`**，
PC 端不做任何感知，也无需改动。

## 3. 载荷封装

### 3.1 明文模式（默认）

消息体本身就是 JSON：

```json
{"t": "text", "seq": 1, "text": "你好"}
```

### 3.2 加密模式

消息体是一个信封，载荷用 **NaCl SecretBox** 加密：

```json
{"e": "<base64( nonce || ciphertext )>"}
```

- 密钥：`SHA256("phonemic-v1|" + token)`，两端各自派生，无需额外握手
- nonce：每条消息随机 24 字节，随密文一起传输
- 明文仍是第 3.1 节那种 JSON

> **当前默认关闭**（`encrypt=false`）。开启：PC 用 `--encrypt`，且两端都装有 libsodium
> （PC: `pynacl`；Android: lazysodium-android）。协商字段见 `auth_ok.encrypt`。

## 4. 消息类型

### 4.1 手机 → 电脑

| `t` | 字段 | 说明 |
|---|---|---|
| `auth` | `id` 设备 ID，`name` 设备名，`token` 配对令牌 | **必须是第一条** |
| `text` | `seq`，`text`，`mode`（可选，覆盖 PC 端注入模式） | 整句识别结果，注入到光标 |
| `typing` | `seq`，`text_partial` | 流式部分结果。**PC 当前只回 ack，不注入**（避免污染撤销栈） |
| `cmd` | `seq`，`text`（自然语言）或 `intent`+`args`（预解析动作） | 走命令层：先查 `commands.json`，查不到可交给 LLM |
| `ping` | — | 心跳 |

### 4.2 电脑 → 手机

| `t` | 字段 | 说明 |
|---|---|---|
| `auth_ok` | `device_name`，`inject_mode`，`encrypt`，`version` | 认证通过 |
| `auth_fail` | `reason` | 认证失败，随后 PC 关闭连接（code 4401） |
| `ack` | `seq`，`ok`，`mode`，`chars`，`partial`（可选） | 注入完成回执 |
| `cmd_result` | `seq`，`ok`，`action`，`detail`，`needs_confirm`（可选） | 命令执行结果 |
| `pong` | `ts` | 心跳回执 |
| `error` | `code`，`msg` | `code` 见下 |

### 4.3 error.code

| code | 含义 |
|---|---|
| `bad_frame` | 帧不是合法 JSON / 解密失败 |
| `unauth` | 未认证就发业务消息 |
| `unknown_type` | 未知的 `t` |
| `internal` | PC 端内部异常 |

## 5. 时序示例

### 5.1 整句听写

```
phone                                    pc
  |-- auth {id,name,token} -------------->|
  |<-- auth_ok {device_name,inject_mode} -|
  |-- text {seq:1, text:"今天天气不错"} --->|
  |                    (剪贴板 + Ctrl+V)  |
  |<-- ack {seq:1, ok:true, chars:7} -----|
```

### 5.2 语音命令

```
  |-- cmd {seq:2, text:"截图"} ----------->|
  |              (查 commands.json 命中)  |
  |<-- cmd_result {ok:true,action:"hotkey",
  |                detail:"win+shift+s"} -|
```

### 5.3 需要确认的危险命令

```
  |-- cmd {seq:3, text:"关机"} ----------->|
  |<-- cmd_result {ok:false,               |
  |                needs_confirm:true,     |
  |                detail:"shutdown ..."} -|
  |-- cmd {intent:{"action":"shell",       |
  |         "cmd":"...","confirm":false}} ->|   // 用户在手机上点了确认
  |<-- cmd_result {ok:true, ...} ---------|
```

## 6. 动作 schema（`cmd` 使用）

```json
{"action": "hotkey",    "keys": ["win","shift","s"]}
{"action": "launch",    "target": "notepad.exe"}
{"action": "shell",     "cmd": "rundll32.exe user32.dll,LockWorkStation", "confirm": true}
{"action": "text",      "text": "原样输入"}
{"action": "clipboard", "text": "复制到剪贴板"}
```

`launch` 的 `target` 可以是可执行文件名、完整路径，或 `http(s)://` URL（会交给默认浏览器）。

## 8. 中转（VPS relay，跨局域网）

手机与 PC 不在同一网络时，双方都**主动出站**连一台部署在 VPS 上的中转服务器
（`vps/relay_server.py`），中转按房间转发帧。它**不解析业务消息、看不到配对
令牌**：第 2 节的 `auth` 认证照旧端到端进行，第 3.2 节的加密在中转之上依然成立。

```
手机(任意网络) ──ws/wss──> VPS 中转 <──ws/wss── PC agent(任意网络)
```

### 8.1 端点

| 角色 | URL | 说明 |
|---|---|---|
| PC | `ws(s)://<relay>/pc?p=<pc_id>&k=<relay_key>` | 注册房间，断线指数退避重连（1s→30s） |
| 手机 | `ws(s)://<relay>/phone?p=<pc_id>` | 拨号进入房间 |

- **房间 id**：`pc_id = "pm" + SHA256("phonemic-relay-v1|" + relay_key) 的前 12 位 hex`。
  PC 与中转各算一遍，中转校验 `p == 派生(k)`，不匹配即关（close 4401）——
  知道 `pc_id` 但不知道 key 的人无法抢注房间。
- 房间同时最多一对 PC/手机。手机先到而 PC 不在线：中转发
  `{"t":"error","code":"pc_offline","msg":...}` 后关闭；房间已有手机：`code:"busy"`。
- 手机被顶替/对端离开时中转直接关连接；PC 端收到关闭后自动重注册，
  手机端按既有断线逻辑重连。同一 `pc_id` 的新 PC 注册会踢掉旧连接（close 4402）。
- 中转与两端之间依赖 WebSocket 协议级 ping/pong 保活（20 s）。

### 8.2 配对（中转模式）

PC 端配置了 `relay_url` 后，二维码内容变为：

```
phonemic://<relay-host>:<port>?v=1&t=<token>&p=<pc_id>&n=<电脑名>&m=relay&s=<0|1>
```

与第 2 节的区别：主机部分填**中转地址**而非局域网 IP；新增 `p`（房间 id）与
`m=relay`（模式标记）；`s=1` 表示用 `wss`，`s=0`/缺省为 `ws`。`t` 仍是
**PC 的配对令牌**（端到端，中转不接触）。手机解析出端点
`ws(s)://<relay-host>:<port>/phone?p=<pc_id>`，其余流程（auth、业务消息）不变。

手动输入两种形态都接受：`192.168.1.3:8765?t=xxx`（直连）、
`wss://relay.example.com:8766/phone?p=pmxxxx&t=xxx`（中转，按 `/phone` 路径识别）。

### 8.3 多电脑

不变：一台电脑一个条目（中转条目自然带自己的 `pc_id` 与令牌），
手机侧列表点选切换 = 断开旧连接、对新目标重新走一遍 `auth`。

## 9. 版本演进约定

- `v` 字段递增时，PC 端 `auth_ok.version` 回传自己支持的版本，手机按低版本协商
- 新增消息类型必须向后兼容：旧端收到未知 `t` 回 `unknown_type`，不应当断连
