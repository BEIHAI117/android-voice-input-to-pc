# 异常退出对 PC Agent 的影响分析

> 结论先行：**现在各种异常退出都不会造成持久损害**，最多几秒钟不可用，手机会自动重连。
> 唯一真正的风险（断电写坏配置丢 token）已经修掉了。

---

## 一、Agent 在磁盘上保存了什么

| 文件 | 内容 | 何时写 | 坏了会怎样 |
|---|---|---|---|
| `config.json` | **配对令牌**、端口、注入方式 | 启动时、设置变更时 | **令牌丢失 → 手机必须重新扫码**（最严重） |
| `commands.json` | 语音命令表 | 首次运行时 | 命令全部失效（静默） |
| `trust.json` | 已配对设备 | 配对时 | 需重新配对 |
| `agent.log` | 运行日志 | 持续追加（5MB×4 轮转） | 无影响 |

**关键点：`config.json` 里是配对令牌。** 它一旦写坏，PC 端会当成"没有令牌"而重新生成一个随机值，
手机里存的旧令牌就对不上了，表现为"连接被拒绝"，必须重新扫码绑定。

## 二、已做的防护

### 1. 原子写入（本次修复）

之前 `config.json` / `commands.json` / `trust.json` 都是直接 `write_text()`——
**如果断电或被杀正好发生在写入中途，文件会被截断**，就是上面说的丢 token 场景。

现在改成「写临时文件 → `os.replace()` 原子替换」。Windows 上 `os.replace` 是原子的：
要么旧文件完整保留，要么新文件完整生效，不存在"写了一半"的状态。
最坏情况是留下一个 `.tmp` 残骸，无害，下次写入会覆盖。

### 2. 文件日志（本次新增）

`%LOCALAPPDATA%\PhoneMic\agent.log`，5MB 轮转、保留 4 份。
崩溃后人工看这个文件就能定位原因，桌面上的「PhoneMic 日志.bat」可以直接跟随查看。

### 3. 看门狗自动重启（桌面启动脚本内置）

Agent 进程退出 → 3 秒后自动拉起。只有「关闭 PhoneMic PC 端.bat」留下的停止标记
才会真正停住，避免"想停却停不下来"。

### 4. 手机端自动重连

WebSocket 断开后按 1s → 2s → 4s … 30s（封顶）指数退避重连，**不需要人工干预**。
实测：重启 PC 端后，手机在几秒内自动连回来（`connection from ... authenticated vivo V2546A`）。

## 三、逐场景分析

| 场景 | 发生了什么 | 影响 | 恢复 |
|---|---|---|---|
| **正常关闭**（关窗口 / Ctrl+C） | 进程干净退出 | 无 | 双击启动脚本 |
| **崩溃**（未捕获异常） | 进程死亡，看门狗 3 秒后重启 | 3~5 秒不可用；崩溃瞬间正在注入的那条会丢 | **自动** |
| **被任务管理器/taskkill 杀掉** | 同崩溃，只是没有清理钩子 | 同上 | 看门狗**自动**（若是由启动脚本拉起的） |
| **断电 / 强制关机** | 进程死亡，可能正赶上写文件 | 修复前：可能丢 token；**修复后：无损**（`.tmp` 残骸无害） | 开机后自启，手机自动重连 |
| **重启电脑** | 进程死亡 | 无 | **开机自启**（已配置），手机自动重连 |
| **睡眠 / 休眠** | 进程被冻结，不退出 | 唤醒后死连接由 20 秒 ping/pong 探测到并重连 | **自动** |
| **网络闪断 / 换 WiFi** | WebSocket 断开 | 手机持续重连 | **自动** |
| **端口未释放？** | 监听套接字被杀时立即关闭；TIME_WAIT 只出现在已建立的连接上，不妨碍重新 bind 监听端口 | 无 | 实测本次会话重启了 6+ 次，从未遇到"地址被占用" |

## 四、仍会丢的东西（无法避免，影响很小）

- **崩溃瞬间正在注入的那一句话**。窗口期小于 1 秒，且 PC 端还没回 ack，
  手机端那条已从发送队列移除，不会重发造成重复输入。
- 若磁盘写满，文件日志会静默失败（控制台输出仍正常）。

## 五、两个建议

1. **别用任务管理器杀 `python.exe` 时误伤其它脚本**。用桌面的「关闭 PhoneMic PC 端.bat」，
   它只匹配命令行里含 `-m agent` 的进程，不会碰你的 `harvest_all.py`、`collect_worker.py` 等。
2. **429 限流**：Agent 每次说话只发 1 次请求（首次另加 1 次接口探测，之后有缓存）。
   如果你同时跑着共用这个 key 的其它脚本，配额是共享的，会互相挤。可以在 mimo 后台看用量，
   或给其它脚本换一个 key。

## 六、桌面上现在有什么

| 文件 | 作用 |
|---|---|
| `启动 PhoneMic PC 端.bat` | 启动（带看门狗，崩溃自动重启；已在运行则提示） |
| `关闭 PhoneMic PC 端.bat` | 停止（只杀 `-m agent`，不碰其它 python） |
| `PhoneMic 日志.bat` | 实时查看运行日志 |

开机自启：已放入 `shell:startup`（`PhoneMic PC 端.lnk`，最小化运行）。
编码说明：批处理是 **GBK** 编码——中文 Windows 的 cmd 用 GBK 解析 .bat，
存成 UTF-8 会被读成乱码导致脚本根本不执行（我第一次就踩了这个）。
