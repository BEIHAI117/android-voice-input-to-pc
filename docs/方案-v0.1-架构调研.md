# 手机悬浮球 → 电脑光标语音输入 + 轻量语音 Agent · 技术方案 v0.1

> 目标平台：Android（首发适配 vivo OriginOS 6）
> 形态：启动后常驻悬浮球，**长按说话**，识别结果直送**绑定电脑的输入光标**；支持简单自然语言操作电脑（去键盘化）。
> 本文档为调研 + 架构提案，等待确认后再进入详细设计与开发。

## 一、开源项目调研结论

### 1.1 同类"手机→电脑光标"方案（最直接的对标）

| 项目 | Star | 技术栈 | 核心做法 | 可借鉴 | 不满足本需求之处 |
|---|---|---|---|---|---|
| [FreeAccHub/qaa-airtype](https://github.com/FreeAccHub/qaa-airtype) | 256 | Python + Flask + PyAutoGUI/Pyperclip | 手机开网页，用**手机输入法（豆包语音）**说话，文本经 LAN 发到 PC 注入光标 | 极简链路、扫码连接、保存最近 10 条 | 非原生 App，无悬浮球，依赖输入法 |
| [franj/PhoneMic](https://github.com/franj/PhoneMic) | 46 | Python(PySide6 + Starlette/Uvicorn) + PyAutoGUI/Pyperclip | 扫码连接 + **端到端加密（NaCl）**；剪贴板注入 / 模拟键盘逐字注入双模式；`commands.json` 命令映射；cloudflared 跨网 | **配对与加密设计、双注入模式、命令配置文件** | 依赖手机输入法、Windows 专用、非原生悬浮球 |
| [bi-boo/luobi-nextype](https://github.com/bi-boo/luobi-nextype) | 62 | HTML/JS | "手机变麦克风，语音输入直达电脑光标" | 交互范式命名 | 同上 |
| [QAA-Tools/qaa-airtype](https://github.com/QAA-Tools/qaa-airtype) | 83 | HTML/JS | qaa-airtype 的 Web 版 + Cloudflare Workers 跨网 | 跨网扩展思路 | 跨网安全性弱 |
| [alone-tree/TextDrop](https://github.com/alone-tree/TextDrop) | 10 | Python | 浏览器打字/说话 → Windows 光标 | — | 无语音深度 |
| [keyux56-spec/ayuvoice-windows](https://github.com/keyux56-spec/ayuvoice-windows) | 6 | — | 扫码→说话→PC 光标 | — | 同上 |
| [simplty/whisper-input](https://github.com/simplty/whisper-input) | 6 | Python | PC 端语音输入法（离线） | PC 端离线识别思路 | 不是手机方案 |
| [caozx1110/Carbon](https://github.com/caozx1110/Carbon) | 10 | HTML/JS | PC 语音助手：听写 + **唤醒词 + 命令执行** | 唤醒词 → 命令执行的 Agent 雏形 | 跑在电脑端 |

**结论**：这个方向的开源实现全部是「手机网页 / 手机输入法 + PC 端注入脚本」，**没有一个原生 Android 悬浮球 App**。也就是说，App 本体需要自研，但链路两端（PC 注入、配对加密、命令映射）可以大量抄 PhoneMic / qaa-airtype 的设计。

## 二、待确认的核心决策（请拍板）

### 决策 1：语音识别在哪跑？

| 方案 | 延迟 | 准确率 | 离线 | 包体/成本 | 评价 |
|---|---|---|---|---|---|
| **A1. 本地 sherpa-onnx（SenseVoice/Paraformer）** | 300ms~1s | 中上（中文很好） | ✅ | 模型 30~80MB（首次下载） | **推荐主用** |
| A2. 云端 ASR（豆包/讯飞/阿里/OpenAI 兼容） | 500ms~2s | 高 | ❌ | 需 Key、计费 | 精度优先场景的补充 |
| A3. 复用手机输入法语音（豆包/讯飞输入法） | 依赖输入法 | 很高 | 依赖输入法 | 零成本 | **MVP 最快路径**，但失去产品自主性 |

> 推荐：**A1 为主 + A2 可切换 + A3 作为可选"输入法模式"**。

### 决策 2：识别文本怎么到电脑？

| 方案 | 是否装 PC 端 | 能否做 Agent | 评价 |
|---|---|---|---|
| **B1. 局域网 + PC Agent（WebSocket + 二维码配对）** | 要 | ✅ | **推荐**。稳定、可扩展、可加密 |
| B2. BLE HID（手机当蓝牙键盘） | 不要 | ❌（无回传） | 作为免安装兜底，国产 ROM 兼容性风险 |
| B3. 浏览器网页版（qaa-airtype 模式） | 要 | 弱 | 只作为 PoC，不满足"启动后悬浮球" |

### 决策 3：PC Agent 技术栈

| 方案 | 优点 | 缺点 | 评价 |
|---|---|---|---|
| **C1. Python + FastAPI/Starlette + PyAutoGUI + Pyperclip** | 上手快，可直接抄 PhoneMic | 打包体积大（~60MB+）、常驻占内存 | **推荐原型/MVP** |
| **C2. Rust + Axum + enigo** | 单文件 exe（~10MB）、稳、省资源 | 开发量大 | **推荐正式版** |
| C3. C#/WPF + SendInput | 原生 Windows、体积小 | 只能 Windows | Windows-only 可选 |

## 三、推荐总体架构（方案 A = B1 + A1 + C2/C1）

```
┌──────────────────────── Android 手机（OriginOS 6）────────────────────────┐
│                                                                            │
│  悬浮球 (ForegroundService + TYPE_APPLICATION_OVERLAY)                      │
│    ├─ 手势层: 长按=说话 / 松开=发送 / 双击=唤醒开关 / 拖动 / 边缘吸附          │
│    ├─ 录音层: AudioRecord 16kHz 单声道 PCM（可加 AEC/AGC）                  │
│    ├─ 识别层: sherpa-onnx                                                    │
│    │     ├─ VAD (Silero)  端点检测                                          │
│    │     ├─ ASR  SenseVoice / Paraformer-streaming  → 中文                 │
│    │     └─ KWS  唤醒词（"你好小智"）可选                                    │
│    ├─ 传输层: OkHttp WebSocket + NaCl(端到端加密)                            │
│    ├─ 配对层: 扫二维码（含 IP+端口+公钥）/ 手动输码                           │
│    └─ 设置页: 识别源切换、注入方式、命令表、开机自启引导                       │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               │  LAN  WebSocket (JSON / msgpack)
                               │  QR 配对 + NaCl box 加密
┌──────────────────────────────▼─────────────────────────────────────────────┐
│                          PC Agent（Windows 先行）                           │
│    ├─ 服务层: WebSocket/HTTP server + mDNS 发现 + 二维码生成                 │
│    ├─ 注入引擎:                                                            │
│    │     ├─ 模式1【默认】剪贴板 + Ctrl+V（中文可靠）                         │
│    │     └─ 模式2 模拟键盘逐字（终端/SSH/vim 场景）                          │
│    ├─ Agent 层:                                                            │
│    │     ├─ L0 关键词 → 命令映射（commands.json，参考 PhoneMic）             │
│    │     ├─ L1 可选 LLM 意图解析（OpenAI 兼容/Ollama）→ tool-calling         │
│    │     └─ 动作库: 启动程序 / 全局快捷键 / Shell / 剪贴板 / 截图回传          │
│    └─ 托盘 + 状态提示 + 连接管理                                             │
└────────────────────────────────────────────────────────────────────────────┘
```

## 四、模块划分

### 4.1 手机端 App（Kotlin，单模块起步，后期拆分）

| 模块 | 职责 | 关键技术 |
|---|---|---|
| `overlay` | 悬浮球 View、手势、吸附、拖动、多状态动画 | `WindowManager` + `TYPE_APPLICATION_OVERLAY` |
| `service` | 前台服务保活、开机自启、厂商白名单引导 | `ForegroundService` + 通知常驻 |
| `audio` | AudioRecord 录音、AEC/AGC、音量/波形反馈 | `AudioRecord` 16kHz mono PCM |
| `asr` | VAD / ASR / KWS，识别源抽象（本地/云/输入法） | sherpa-onnx Android API |
| `net` | WebSocket 客户端、心跳、重连、断线提示 | OkHttp / Ktor client |
| `pair` | 扫码、公钥交换、设备绑定与解绑 | ZXing ML-Kit + libsodium-jni |
| `settings` | 设置项、权限引导页、OriginOS 适配检测 | Jetpack Compose + DataStore |
| `agent_ui`（V1） | 快捷指令面板、历史记录、命令回执 | Room + Compose |

### 4.2 PC Agent

| 模块 | 职责 | MVP 选型 |
|---|---|---|
| `server` | WebSocket/HTTP、二维码、设备鉴权 | FastAPI/Starlette（正式：Axum） |
| `inject` | 文本注入（剪贴板/模拟键盘） | PyAutoGUI + Pyperclip（正式：enigo） |
| `agent` | 命令解析与动作执行 | JSON 规则 → 可选 LLM |
| `ui` | 托盘、连接状态、设置 | pystray（正式：Tauri/tray-icon） |
| `security` | 配对、加密、命令白名单 | PyNaCl / libsodium |

### 4.3 通信协议（草案）

WebSocket，JSON（正式版可换 msgpack）：

```
phone → pc:
  {"t":"auth","id":..,"pub":"...","nonce":"..."}
  {"t":"typing","seq":12,"text_partial":"今天天气"}        // 流式上屏（可选）
  {"t":"text","final":true,"text":"今天天气不错","ts":...}  // 整句提交
  {"t":"cmd","intent":"open_app","args":{"name":"微信"}}
  {"t":"ping"}

pc → phone:
  {"t":"auth_ok","pair_id":"..."}
  {"t":"ack","seq":12,"ok":true,"mode":"clipboard"}
  {"t":"cmd_result","intent":"open_app","ok":true}
  {"t":"pong"}
```

## 五、关键时序

```
用户长按悬浮球
  → App 抬起前台 + 开始 AudioRecord
  → 悬浮球变"录音中"（波形/震动反馈）
  → VAD 起判 → sherpa-onnx 流式识别（可选逐句 partial 上屏）
用户松手
  → 截断音频 → 终识别 → 文本去标点/规整
  → WebSocket 发送 text.final
  → PC Agent 收到 → 注入引擎（剪贴板 + Ctrl+V）
  → ack 回执 → 手机端短暂提示"已输入"（震动/气泡）

若判定为命令（"打开微信""截图""静音"）
  → 走 Agent 层 → 执行动作 → 回传结果（可选语音播报/气泡）
```

## 六、OriginOS 6 / vivo 适配清单（必须做）

| 项 | 说明 | 处理 |
|---|---|---|
| 悬浮窗权限 | `SYSTEM_ALERT_WINDOW` | 设置→应用→权限→悬浮窗，App 内引导跳转 |
| **后台弹出界面** | vivo 专有开关，**不打开则后台无法弹悬浮球** | 引导页检测 + 跳转 vivo 设置（`com.iqoo.secure` / 设置内搜索） |
| 自启动 / 关联启动 | 否则被杀后无法自动拉起 | 引导用户加入白名单 |
| 电池后台耗电 | 设为"不计耗电/无限制"，防止深度休眠断连 | 引导 + 前台服务 |
| 锁屏悬浮球 | 需允许锁屏显示上层 | 权限引导 |
| 麦克风 | `RECORD_AUDIO`（运行时） | 首次长按申请 |
| 前台服务通知 | Android 14+ 需 `FOREGROUND_SERVICE_*` 类型声明 | manifest + 常驻通知 |
| 麦克风隐私指示 | Android 12+ 状态栏绿点 | UI 上说明，非阻塞 |
| 小窗/游戏模式 | 部分场景会屏蔽悬浮球 | 文档说明 + 兜底通知栏快捷按钮 |

> 同类 ROM（MIUI/ColorOS/鸿蒙）也有对应白名单开关，适配层做成"厂商策略表"，首发只做 vivo，后续补。

## 七、安全与隐私

1. **只在局域网**：默认不暴露公网；跨网（V2）用中继隧道并强制 E2E 加密。
2. **配对必须**：二维码内含 `IP:PORT + 设备公钥 + 随机 token`；首次连接 PC 弹 4 位确认码（参考 PhoneMic）。
3. **端到端加密**：NaCl `crypto_box`（libsodium），PC 公钥经二维码带外传递。
4. **命令白名单**：`commands.json` 之外的动作默认禁止；Shell 类动作二次确认。
5. **音频不落盘**：识别完成后即丢弃音频；提供"仅本地识别"开关以示隐私承诺。

## 十、需要你拍板的问题

1. **ASR 首选**：本地 sherpa-onnx（推荐，隐私好/离线）还是云端 API（更准）？是否接受模型首包下载 30~80MB？
2. **PC 端目标系统**：先只做 Windows？还是同时要 macOS/Linux？
3. **PC 端技术栈**：Python 原型先行 → Rust 正式版（推荐）；还是直接 Rust；还是 C#/WPF？
4. **Agent 深度**：只要「关键词 → 快捷键/命令」级别的映射（V1 就能做），还是要 LLM 理解任意自然语言并调用工具（V2）？
5. **是否需要免安装模式**（BLE HID，手机当蓝牙键盘，不用装 PC 端）？作为兜底还是主线？
6. **是否需要跨网使用**（人在外面用家里/公司电脑）？需要则引入中继隧道与更强鉴权。
7. **隐私红线**：是否允许音频/文本出网？（决定能否上云识别与 LLM Agent）
8. **是否要"唤醒词"**（免长按，喊名字说话）？会增加功耗与误触发。
