# PhoneMic 中转服务 · VPS 部署对接文档

> **给谁看**：负责这台 VPS 的操作员（人或 AI 助手）。照本文一步步执行即可，
> 不需要理解 PhoneMic 的业务逻辑，全部操作约 10~15 分钟。
>
> **任务一句话**：在一台有公网 IP 的 VPS 上，把 `relay_server.py` 跑起来
> （systemd 常驻），配好 TLS 与防火墙，跑通自检，最后把**中转地址**回执给用户。

## 1. 背景：这个东西是干嘛的

PhoneMic 是"手机说话 → 电脑打字"的工具。手机和电脑平时走局域网直连；
当两者**不在同一个网络**（手机用流量、人在公司/外地）时，需要一台
公网中转服务器转发 WebSocket 消息：

```
手机(任意网络) ──ws/wss──> [VPS 中转 relay_server.py] <──ws/wss── 用户电脑(任意网络)
```

- **手机和电脑都主动出站连过来**：VPS 只需入站放行一个端口，不涉及用户的路由器。
- 中转只做"按房间转发字节"，**不解析业务内容**。真正的鉴权（配对令牌）发生在
  手机↔电脑端到端，中转接触不到。
- 连接形态：两种 WebSocket 路径
  - `/pc?p=<房间ID>&k=<密钥>` —— 用户电脑注册房间（长期在线，断线自动重连）
  - `/phone?p=<房间ID>` —— 手机临时拨号
- 每台用户电脑一个房间；一台中转可以同时服务多台电脑，互不干扰。

## 2. 前置条件（先确认再动手）

| 项 | 要求 | 不满足时的处理 |
|---|---|---|
| VPS 系统 | Linux（Ubuntu/Debian 示例，其他发行版等价替换包管理命令） | — |
| Python | **3.10+**（`python3 --version`） | 用系统包或 pyenv 装新版 |
| 端口 | 对外放行一个 TCP 端口：**8766**（无域名方案）或 **443**（有域名方案） | 云厂商安全组 + 系统防火墙都要放行 |
| 域名 | **强烈建议**有一个解析到 VPS 的域名（用于 HTTPS 证书） | 没有域名也能跑，见 §5 方案 C |
| 权限 | root 或 sudo；能 `systemctl` 操作服务 | — |

需要上传的两个文件（从 PhoneMic 仓库的 `vps/` 目录取，或让用户直接发给你）：

1. `relay_server.py` —— 中转本体（单文件，唯一依赖 `websockets>=13`）
2. `selfcheck.py` —— 部署完的自检脚本

## 3. 标准部署（方案 A：有域名，Caddy 自动 HTTPS —— 推荐）

### 3.1 安装文件

```bash
sudo useradd -r -s /usr/sbin/nologin phonemic
sudo mkdir -p /opt/phonemic-relay
# 把 relay_server.py、selfcheck.py 放进 /opt/phonemic-relay/（scp/sftp 均可）
sudo python3 -m venv /opt/phonemic-relay/venv
sudo /opt/phonemic-relay/venv/bin/pip install "websockets>=13"
sudo chown -R phonemic:phonemic /opt/phonemic-relay
```

此时 relay 监听 `127.0.0.1:8766`（明文，只给本机的 Caddy 反代用）。

### 3.2 systemd 常驻

```bash
sudo tee /etc/systemd/system/phonemic-relay.service > /dev/null <<'EOF'
[Unit]
Description=PhoneMic relay (WebSocket room forwarder)
After=network-online.target
Wants=network-online.target

[Service]
User=phonemic
WorkingDirectory=/opt/phonemic-relay
ExecStart=/opt/phonemic-relay/venv/bin/python /opt/phonemic-relay/relay_server.py --host 127.0.0.1 --port 8766
Restart=always
RestartSec=3
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now phonemic-relay
```

### 3.3 Caddy 反代（自动申请/续期证书，自动支持 WebSocket）

```bash
sudo apt install -y caddy   # 已装则跳过
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
relay.你的域名.com {
    reverse_proxy 127.0.0.1:8766
}
EOF
sudo systemctl reload caddy
```

> 把 `relay.你的域名.com` 换成实际域名（需已把 A 记录指到 VPS IP）。
> 域名建议单独用一个子域，不影响 VPS 上其它服务。

### 3.4 防火墙

```bash
# 云厂商控制台的安全组：放行 TCP 443（HTTP 80 给 Caddy 申请证书用，也放行）
# 系统防火墙（如启用 ufw）：
sudo ufw allow 80,443/tcp
# 8766 只对本机监听，无需对外放行
```

### 3.5 自检验收（必做）

```bash
/opt/phonemic-relay/venv/bin/python /opt/phonemic-relay/selfcheck.py wss://relay.你的域名.com
```

预期输出 **4 项 PASS**：

```
[PASS] 坏 key 被拒
[PASS] PC 注册成功
[PASS] 手机拨号成功
[PASS] 离线房间报 pc_offline
自检通过：中转转发链路正常。
```

有任何 FAIL：把完整输出发回给用户，并附 `journalctl -u phonemic-relay -n 50 --no-pager` 的输出。

## 4. 方案 B：有域名但想用 nginx + certbot

中转本体仍按 §3.1/§3.2 装在 `127.0.0.1:8766`，nginx 站点配置：

```nginx
server {
    listen 443 ssl;
    server_name relay.你的域名.com;
    # ssl_certificate / ssl_certificate_key 按 certbot 常规签发

    location / {
        proxy_pass http://127.0.0.1:8766;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;   # 长连接：PC 端会挂一整天
        proxy_send_timeout 3600s;
    }
}
```

装完同样跑 §3.5 的自检。**注意**：不要在该 server 里开 access_log 记录完整
query（URL 里有注册密钥参数），或至少对 `/pc` 路径关掉日志。

## 5. 方案 C：没有域名（IP 直连，明文 ws://）

手机端 App 允许 `ws://` 明文连接（这是为了局域网场景内置的策略），
但没有证书就有被网络中间人窃听的暴露面。**必须同时让用户开启端到端加密**：

1. relay 直接对外监听：

   ```bash
   # 修改 unit 的 ExecStart 为：
   ExecStart=/opt/phonemic-relay/venv/bin/python /opt/phonemic-relay/relay_server.py --host 0.0.0.0 --port 8766
   ```

2. 防火墙放行 TCP 8766。
3. 自检：`/opt/phonemic-relay/venv/bin/python /opt/phonemic-relay/selfcheck.py ws://<VPS公网IP>:8766`
4. 回执给用户时**必须附上这句话**：
   > 中转是明文链路，请在 PC 端启动参数里加 `--encrypt`，并在手机 App
   > 设置里……（如 App 暂无该开关，先使用明文模式，风险自担；建议尽快补一个域名）

   > 说明：PhoneMic 两端已内置 NaCl 载荷加密（PC 加 `--encrypt`），开启后
   > 中转链路上传输的听写内容与令牌均为密文，可显著降低明文风险。

## 6. 验收清单（全部满足才算完成）

| # | 检查项 | 命令 / 方法 | 预期 |
|---|---|---|---|
| 1 | 服务常驻 | `systemctl is-active phonemic-relay` | `active` |
| 2 | 开机自启 | `systemctl is-enabled phonemic-relay` | `enabled` |
| 3 | TLS 有效（方案 A/B） | 浏览器开 `https://relay.你的域名.com/` | 返回 426 Upgrade Required 或握手错误页均可（证明端口通） |
| 4 | 自检 4 项 PASS | `/opt/phonemic-relay/venv/bin/python /opt/phonemic-relay/selfcheck.py <中转URL>`（**必须用 venv 的 python**，系统 python3 没有 websockets 模块） | 全 PASS |
| 5 | 断线恢复 | `sudo systemctl restart phonemic-relay` 后再跑一次自检 | 依旧全 PASS |

**完成后回执给用户（复制模板改填）：**

```
PhoneMic 中转已部署完成：
- 中转地址：wss://relay.你的域名.com        （或 ws://IP:8766）
- 已通过 selfcheck 4 项自检
- 服务：systemd 常驻 phonemic-relay，开机自启，日志 journalctl -u phonemic-relay
- 注意事项：（方案 C 时写明"明文链路，建议开 --encrypt"）
```

用户拿到地址后的动作（**不需要你做**，仅供你了解）：
电脑端 `python -m agent --relay <中转地址>` 重启一次；手机重新扫 PC 端二维码。
联调通过的标志：手机悬浮球变 `●`，且 VPS 日志里出现 `pc <房间ID>: registered` 和 `phone -> <房间ID>: paired`。

## 7. 运维速查

| 场景 | 命令 |
|---|---|
| 看日志 | `journalctl -u phonemic-relay -f` |
| 重启 | `sudo systemctl restart phonemic-relay` |
| 升级代码 | 覆盖 `/opt/phonemic-relay/relay_server.py` 后 `systemctl restart phonemic-relay` |
| 端口被占 | `ss -ltnp | grep 8766` 查占用者 |
| 检查在线房间 | 日志里找 `registered` / `unregistered` 行 |

日志含义：`pc <ID>: registered`=某台电脑已上线；`phone -> <ID>: paired`=手机进入会话；
`pc_offline`=手机来拨号但对应电脑没上线（用户侧电脑没开程序，不是故障）。

## 8. 安全说明

- relay **无状态、无账号体系**：房间由用户的密钥自证，注册校验
  `pc_id == "pm" + sha256("phonemic-relay-v1|key")[:12]`，不需要在 VPS 上维护白名单。
- 不落盘任何用户数据；日志只有房间 ID 与连接事件，没有业务内容。
- 若 VPS 仅供单人使用，可用云防火墙把来源 IP 限制到常用出口网段（可选加固）。
- 公网服务建议保留基础防护：fail2ban / 云 WAF 可选，非必需。

## 9. 边界与约定

- 中转协议版本跟随 PhoneMic 协议 v1（`docs/协议.md` §8）；升级由用户发起新文件，操作员只做"覆盖 + 重启"。
- 一个房间同时只允许一对 PC/手机；第二部手机拨号会收到 `busy`，属正常设计。
- 中转不兼容 HTTP/1.0 代理与部分企业级 TLS 中间盒；如用户反馈"自检过但手机连不上"，优先怀疑手机侧网络对 WebSocket 的限制（换热点验证），再查反代超时配置。
